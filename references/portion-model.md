# 份量与浪费模型

## 1. 目标

回答一个问题：**这一顿到底点多少才刚刚好。**

不是最便宜，不是热量最低，而是「吃得完、吃得饱、不浪费」。因此模型的核心输出是三档方案，以及每档的**预估浪费率与浪费金额**。

## 2. 胃口线（能量口径）

```
need_kcal = 700 × people
          × appetite_factor
          × scene_factor
          × dining_factor
          × feedback_factor
```

| 因子 | 取值 |
|---|---|
| `appetite_factor` | light 0.85 / normal 1.00 / heavy 1.18 |
| `scene_factor` | solo 1.00 / pair 0.90 / family 0.92 / work 0.95 / night 0.82 |
| `dining_factor` | dine_in 1.00 / takeout 0.97 / delivery 0.95 / drive_thru 1.00 |
| `feedback_factor` | 由历史反馈推导，初始 1.00，区间 [0.75, 1.35] |

`pair` 取 0.90 是因为两人同行时小食与饮品会共享，人均需求低于独食之和。

## 3. 饱腹单位

单份餐品的饱腹贡献：

```
satiety = min(kcal, 900) / 100            # 能量项，单品能量截断避免超大单品失真
        + protein / 10 × 0.35             # 蛋白质项
        + min(kcal, 900) / 100 × solid × 0.25   # 固形物项
        + min(sodium, 2000) / 1000 × 0.3  # 钠项
```

`solid` 为固形物系数，由餐品类别给出：主食约 1.0、小食 0.55–0.85、甜品 0.5、饮品 0.2–0.35。

换算系数：

```
target_satiety = need_kcal × tier_factor × 1.28 / 100
```

`1.28` 是把能量口径折算到饱腹口径的经验系数，与单份饱腹公式保持一致量纲。

## 4. 三档目标

| 档位 | `tier_factor` | 含义 |
|---|---|---|
| 保守 | 0.80 | 不饿、想控制摄入 |
| 刚好 | 1.00 | 贴近胃口线 |
| 丰盛 | 1.18 | 很饿或两人分享 |

## 5. 评分

```
score = 100
      - 45 × 相对偏差
      - 80 × max(0, 相对偏差 - 0.20)     # 偏离过远的额外惩罚
      - 30（若 |相对偏差| > 15%）
      - 25 × 浪费率
      - 1.6 × (价格 / 10)
      - 预算惩罚（超预算时按超出比例计算）
      - 15 × 未满足软目标数
```

相对偏差带 3% 容差；超出胃口线方向的偏差按 1.8 倍加权，因为多点比少点更容易产生浪费。

## 6. 组合选择策略

1. **候选构造**：全量单品与双品组合 + 贪心种子的一步/两步变异。组合数量恒定可控，无需截断。
2. **锁定刚好档**：在候选中取分数最高者作为基准。
3. **派生三档**：保守档在基准下方取最优，丰盛档在基准上方取最优，保证三档单调且互不相同。
4. **件数上限**：`min(12, 4 + 3 × 人数)`，避免多人场景反而选不出组合。

## 7. 浪费估算

```
超出比例 = (kcal - need_kcal) / kcal
浪费率   = 超出比例 × 丢弃系数 × 档位放大
浪费金额 = 组合价格 × 浪费率
```

| 就餐方式 | 丢弃系数 |
|---|---|
| dine_in | 0.75 |
| takeout | 0.40 |
| delivery | 0.40 |
| drive_thru | 0.55 |

堂食吃不完大多直接丢弃，外带与麦乐送可以带走，因此丢弃系数更低。丰盛档额外乘 1.15，因为超过胃口线越多越容易剩。

## 8. 反馈闭环

餐后一句反馈即可更新 `feedback_factor`：

| 反馈 | 调整 |
|---|---|
| 没吃够 `under` | `factor × 1.06` |
| 刚好 `fit` | 不变 |
| 有剩余 `over` | `factor × 0.94` |

系数上限 1.35、下限 0.75。多次反馈会逐步收敛到个人真实食量。

## 9. 边界与免责

- 模型用于**份量估算**，不用于营养治疗或疾病管理。
- 营养数据来自麦当劳官方 MCP `list-nutrition-foods`，餐品、价格与供应状态以官方实时结果为准。
- 浪费率为统计意义上的估算，不是对单次就餐结果的承诺。
